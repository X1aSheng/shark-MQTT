## 4. 行为变更与升级注意(部署前必读)

1. **metrics 默认值**:`metrics_enabled` 默认改为 `true`(与既有"开箱即用 /metrics"行为一致);
   设为 `false`(env `MQTT_METRICS_ENABLED=false` 或配置文件)可关闭 `/metrics`,
   `/healthz`、`/readyz` 始终可用(k8s 探针不受影响)。
2. **环境变量现在生效**:CLI 不再需要 `-config` 才会读取 `MQTT_*`;优先级为
   默认值 < 环境变量 < 配置文件 < 显式命令行参数。此前 deploy 清单中的
   `MQTT_LOG_LEVEL`/`MQTT_LOG_FORMAT` 等现在真正生效;k8s app 清单已改为挂载并
   传入 `-config=/etc/shark-mqtt/config.yaml`。
3. **认证入口**:生产环境请用 `-auth-file users.yaml`(或 `auth_file`/`MQTT_AUTH_FILE`),
   不再只能二选一(deny-all / `--allow-all`)。
4. **服务端 keep-alive**:`cfg.KeepAlive`(默认 60s)现在会通过
   `WithBrokerKeepAlive` 生效——仅覆盖"客户端请求值更大"的场景(MQTT 5 同时下发
   ServerKeepAlive);`KeepAlive=0` 客户端语义不变,僵尸回收依赖 TCP keepalive
   (现对 TLS/WS/WSS 同样生效)与写超时。
5. **存储键格式变更(Redis/Badger 消息队列)**:离线消息键由
   `mqtt:message:<clientID>:<id>` 变为 `mqtt:message:<len>:<clientID>:<id>`。
   旧版本遗留的键不会被新前缀扫描命中:Redis 侧默认 1h TTL 自愈;Badger 侧建议升级时
   一次性清理旧的 `mqtt:message:` 前缀数据。会话/保留消息键格式未变。
   `store.SessionStore` 新增方法 `RefreshSession`(memory/badger 为 no-op);
   第三方存储实现需补充该方法方可编译。
6. **$SYS 发布**:allow-all(及未配置 ACL)下客户端发布到 `$` 前缀主题被拒绝;
   需要显式授权请通过 Authorizer(如 StaticAuth ACL `$SYS/+`)。

## 5. 遗留事项(建议后续,非本次代码缺陷)

- **WS 边界**:升级前 HTTP 连接不计数/无超时、任意路径可升级、Origin 恒 true
  (设计权衡:MQTT 客户端非浏览器);建议部署层限流或后续提供开关。
- **`-race` 动态验证**:本机无 C 编译器无法运行;建议 CI(cgo 环境)对
  takeover/重连/断连并发场景补 `go test -race`(README 声明 CI 已有 race 全绿能力)。
- **存储命名空间与 schema 版本**:Redis/Badger 键无实例/租户前缀配置、持久化 JSON 无
  schema 版本字段(共享后端/跨版本升级时需自行隔离/迁移)。
- **badger 忽略 ctx**;`options_server.go` 的 server 级选项(writeBufferSize 等)仍无消费者。
- **延迟遗嘱语义**:WillHandler 按 clientID 单槽设计,clean-start 接管场景下旧延迟遗嘱
  可能被新连接注册取消(审计 C#7 语义权衡),如需要可后续按 MQTT 5 Session 维度重做。
- **Go 工具链**:升级到 ≥ 1.26.6 以修复 govulncheck 报告的标准库漏洞
  (GO-2026-6090/5856/4971/4866 等)。
